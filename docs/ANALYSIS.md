## 2. Workflows to preserve

- **Report**: photo (base64), type (Dog/Cat/Bird/Cow/Horse/Other), severity (critical/moderate/mild), description (min 10 chars), location text + GPS (browser geolocation + Nominatim reverse geocode). Case id `SC-n`. Timeline entry "Reported". Fallback coordinates near Chennai when no GPS.
- **Radius expansion**: critical 5/15/30/60 km, moderate 3/10/20/40, mild 2/5/15/30. Expands every 7 s / 11 s / 17 s (demo timings) until accepted. Each expansion adds a timeline entry.
- **Responder**: Accept (reported to accepted), On the Way, Mark Rescued, Completed, Drop Case (back to `reported`, expansion resumes). Responder type sets the `assignedTo` label (NGO Team / Veterinarian / Volunteer).
- **Rewards**: 30/20/10 points per severity, awarded once when a case becomes `rescued`. Milestones 50 Rescuer, 200 Guardian, 500 Hero, 1000 Legend. Certificate button (toast only).
- **Donations**: presets 100/250/500/1000, custom amount (1 to 100000), NGO select, optional name, UPI modal with QR and deep link, "I've Paid" creates an unverified donation. History shows Verified or Processing.
- **Admin**: KPIs (total/active/rescued/critical), critical list, all cases, timeline modal; Force Dispatch to a unit (case goes to `onway`); spam delete; donation verification ledger; pending admin and responder approvals, approve or reject/ban; weekly heatmap from real reports; weekly / monthly / breakdown charts; Export center with 5 categories (weekly, monthly, analytics, donations, full) and CSV / JSON / printable PDF / AI prompt formats.

## 3. What is localStorage or simulated

| Item | Problem | Backend replacement |
|---|---|---|
| `sc_users` and `BUILTIN_USERS` | Plaintext passwords, admin passwords visible in page source | `users` table, bcrypt hashes, seeded from `.env` |
| `sc_state` (reports, donations, points, myAccepted, myCompleted, nextId) | Per browser, not shared between roles | `reports`, `report_events`, `donations`, `users.points` |
| `S.userPoints = 120`, `myAccepted`, `myCompleted` | One global value, not per user | per-user columns and `reports.responder_id` |
| `setTimeout` radius expansion | Stops on refresh, runs only in the reporter's tab | Server-side scheduler (`setInterval`) |
| Pending approval stored as `" (Pending)"` in the name | Pending admins can still log in | `users.status` (active / pending / banned), enforced at login |
| Role checks (`requireAuth`) | Client side only | JWT + role middleware |
| Weekly / monthly / breakdown charts | Hard-coded demo numbers | SQL aggregate endpoints |
| Weekly heatmap | Real data, falls back to demo | Aggregate endpoint |
| Hero stats (`+3`, `+1`), "12 responders" | Fake offsets | `/api/stats/public` |
| Donation verified flag | Client side | Admin-only endpoint |
| Certificate | Toast only | PDF generated by server |
| Export | Built from client state | Server endpoints |
| Force Dispatch unit list | Hard-coded 3 units | Kept as constant list (config) |

## 4. Defects found in the prototype

1. `#page-admin` and its `.container` are never closed before `<script>`.
2. `r.reporter` is read by CSV export but never set.
3. Pending admins can log in (login does not check the Pending suffix).
4. Access Control lists only custom-registered responders/admins, matched by array index; built-in accounts cannot be managed.
5. User-supplied text (description, location, name) is inserted with `innerHTML` (XSS).
6. Photos are base64 in localStorage (quota risk).
7. All responders see all reports; the radius is cosmetic (distance is never computed).
8. `S.chartsInit` is saved into state, so charts do not re-init after reload while the DOM is rebuilt.
9. AI prompt export ignores the chosen category and always uses the full dataset.
10. Weekly PDF silently substitutes demo numbers when the week has no data.
11. Spam list shows only `reported` / `accepted` cases.
12. Responder "Completed" stat starts at hard-coded 1.
